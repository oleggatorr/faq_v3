# Аудиторское логирование (Audit Logs)

## Обзор

> **Статус:** 🚧 В разработке (на этапе планирования)

Система аудиторского логирования предназначена для отслеживания всех значимых действий пользователей в системе.

**Планируемое использование:**
- **Безопасности** — контроль несанкционированного доступа
- **Аудита** — отслеживание изменений данных
- **Отладки** — диагностика проблем
- **Соответствия** — выполнение требований регуляторов

---

## Текущее состояние

На данный момент в системе **уже существует** механизм логирования событий тикетов через таблицу `ticket_events`.

### Текущая система: `ticket_events`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | BIGINT | Первичный ключ |
| `ticket_id` | INT | ID тикета (FK → tickets) |
| `agent_id` | INT | ID агента (FK → agents) |
| `action_type` | VARCHAR(50) | Тип события (см. ниже) |
| `field_name` | VARCHAR(100) | Какое поле изменилось |
| `old_value` | TEXT | Старое значение |
| `new_value` | TEXT | Новое значение |
| `comment` | TEXT | Комментарий |
| `occurred_at` | DATETIME | Время события (авто) |

### Типы событий (`EventType`)

```python
created, replied, status_changed, priority_changed,
assigned, unassigned, category_changed, merged,
closed, reopened, locked, unlocked, anonymized,
archived, unarchived,
note_added, attachment_added, customer_replied
```

### Где используется

- **`app/services/ticket_service.py`** — создаёт события при изменении тикета
- **`app/services/message_service.py`** — создаёт события при ответах
- **`app/services/attachment_service.py`** — создаёт события при добавлении вложений

### Ограничения текущей системы

- ❌ Привязана только к тикетам (`ticket_id` обязательное поле)
- ❌ Не логирует действия вне тикетов (вход/выход, просмотр списка, экспорт)
- ❌ Нет уровня системы (удаление агентов, изменение настроек)
- ❌ Нет IP-адреса, user-agent для аудита безопасности

## Структура данных (планируемая)

### Модель БД: `audit_logs`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | BIGINT | Первичный ключ |
| `agent_id` | INT | ID агента, выполнившего действие (FK → agents) |
| `action` | VARCHAR(50) | Тип действия (login, create, update, delete) |
| `entity_type` | VARCHAR(50) | Тип объекта (agent, ticket, department) |
| `entity_id` | INT | ID объекта, над которым выполнено действие |
| `details` | TEXT | JSON с дополнительными данными |
| `ip_address` | VARCHAR(45) | IP-адрес клиента |
| `user_agent` | VARCHAR(500) | User-Agent браузера |
| `timestamp` | DATETIME | Время события (авто) |

### Индексы

- `ix_audit_logs_agent_id` — для фильтрации по агенту
- `ix_audit_logs_action` — для фильтрации по типу действия
- `ix_audit_logs_entity_type` — для фильтрации по типу объекта
- `ix_audit_logs_timestamp` — для сортировки по времени

## Планируемые события для логирования

### 1. Авторизация

| Событие | Action | Entity Type | Данные в details |
|---------|--------|-------------|------------------|
| Успешный вход | `login` | `agent` | `{"method": "password"}` |
| Неудачный вход | `login_failed` | `agent` | `{"login_attempt": "...", "reason": "invalid_credentials"}` |
| Выход | `logout` | `agent` | `{}` |

### 2. Агенты (операторы)

| Событие | Action | Entity Type | Данные в details |
|---------|--------|-------------|------------------|
| Создание агента | `create` | `agent` | full_name, email, role |
| Изменение агента | `update` | `agent` | changed_fields |
| Удаление агента | `delete` | `agent` | `{"deleted_agent_id": ...}` |

### 3. Тикеты

| Событие | Action | Entity Type | Данные в details |
|---------|--------|-------------|------------------|
| Создание тикета | `create` | `ticket` | track_id, subject, customer_name |
| Создание сообщения (публичное) | `create` | `message` | ticket_id, track_id, customer_name, is_internal, has_attachments |
| Создание сообщения (ответ оператора) | `create` | `message` | ticket_id, is_internal, has_attachments |
| Изменение тикета | `update` | `ticket` | `{"changes": {...}}` |
| Удаление тикета | `delete` | `ticket` | `{"deleted_by": "..."}` |
| Восстановление из архива | `update` | `ticket` | `{"restored_from_archive": true}` |

## Сравнение систем

| Критерий | `ticket_events` (текущая) | `audit_logs` (планируемая) |
|----------|---------------------------|----------------------------|
| Назначение | История тикета | Аудит действий |
| Привязка | Только тикет | Любые ресурсы |
| Для кого | Операторы/клиенты | Админы/безопасность |
| Детализация | Изменения полей | Факт действия + контекст |
| IP/User-Agent | ❌ Нет | ✅ Да |
| Срок хранения | Долго (с тикетом) | Ограниченно (политика) |

## Безопасность

### Что НЕ будет логироваться

- ❌ Пароли (даже хеши)
- ❌ Токены доступа
- ❌ Cookie сессий
- ❌ Полные тела запросов

### Защита данных

- **IP-адреса:** Хранятся в открытом виде (для расследований)
- **Детали:** JSON может содержать чувствительные данные (email, имена)
- **Доступ:** Только администраторы могут просматривать логи
